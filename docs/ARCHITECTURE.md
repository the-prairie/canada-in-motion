# Production data architecture

The initial prototype loaded all detailed well records before first render and exposed workspace files through its development server. The production candidate replaces that design with compact indexes, lazy detail shards and an allowlisted build server. Four dated tariff rows remain independent of well data. Open historical infrastructure and benchmark references form a separately verified context group; benchmark observations never enter quote calculations.

Two alternatives were evaluated against the product's read-only operations. A database and query API centralizes search but adds a hosted database, credentials, background job service and mutable deployment state. Static immutable datasets require no visitor identity, can be served on GitHub Pages, and allow rollback by selecting the previous artifact. Choose static releases with compact indexes and lazy detail shards. This is sufficient for available provincial volumes without transmitting visitor searches or scenario inputs.

The domain has SourceDefinition, SourceSnapshot and ReleaseManifest. SourceDefinition records authority, scope, licence evidence, permitted publication purpose, refresh interval, adapter and schema. SourceSnapshot records retrieval separately from upstream date, content hash, full-source count, dropped-row count, schema validation and publication status. A ReleaseManifest points only to verified content-addressed files. Source failures preserve the last successful release and appear as failed acquisition reports. They never move freshness timestamps forward.

Build all files in a staging directory, validate referential integrity and coverage, then rename into a versioned release. Write the current manifest last. Source count decreases beyond a configured threshold require review. Public packaging is an allowlist. A national-complete gate requires rights and complete coverage for every required province and topic, independently of whether the partial app works.

Recurring acquisition runs in GitHub Actions, with least-privilege read contents and artifact upload. Publishing uses a separate manually enabled environment, a successful refresh and the release gate. Daily refresh can be active before public deployment. Failures are visible as failed workflow runs and uploaded reports. No unverified tariff PDF is converted to an authoritative price. Changes to rate publications require reviewed rate import.

The context group refreshes weekly while well acquisition runs daily. A context manifest preserves the oldest actual acquisition timestamp; intermediate reuse verifies file hashes without resetting that date. All three context assets publish together after successful acquisition and count checks. A report-only beta readiness check evaluates the incomplete candidate but cannot authorize deployment or bypass the national completeness policy.
