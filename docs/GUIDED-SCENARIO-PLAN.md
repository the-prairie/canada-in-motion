# Guided connection scenarios

## Workflow

1. Read the applicable poteto principles and inspect the existing trade and price models. Completed.
2. Frame the task and validate its economic interpretation independently. Completed.
3. Compare an in-place staged guide with a separate full-screen story. Prefer an in-place guide that retains the selected trade, history, Undo and export.
4. Implement the pure scenario contract and behavioral checks before the view. Completed.
5. Add the guided view, lazy source loading, pinned snapshots and URL-backed controls. Completed.
6. Independently review model arithmetic and actual desktop/mobile journeys. Fix material findings. Completed.
7. Run affected regression suites, deploy, verify public assets and public user journeys, and record the release. Completed.

## Definition of done

A user can select a published bilateral trade relationship, change the energy-price assumption, and follow exchange, provincial economy and household-cost views. Every numeric result retains its measure, period, price basis and source. Unsupported model outputs remain unavailable. Exports reproduce the displayed results from pinned inputs. Saved investigations, Undo, URL reload, data failure/retry, keyboard and mobile interactions pass. Independent model and browser reviews pass before public verification.

## Data shape and ownership

Existing workspace selection owns the selected connection, commodity, year and price shock. New guide state owns an active stage, GDP response horizon, household price basis and a separate retail-price shock. The source extension pins the published provincial-price-response and household-cost snapshots when requested. The parent workspace owns this extension so saved investigations and exports retain it. A pure scenario module assembles independently defined channels. The view cannot turn a failed model into a supported result or allocate provincial effects to a bilateral transaction.

## Throughput checkpoint

The highest-risk unknown is the economic interpretation, so an independent modelling agent validates it before presentation choices are fixed. A second agent inspects Follow the Money and reviews the interaction design. The parent owns implementation. Agents own separate review files and checks. Browser testing stays headless. Existing providers, quotas and spending caps remain unchanged. No inference is needed for scenario calculations.

## Decision trail

- Reuse the published models and acceptance screens. No new accuracy claim or model promotion is proposed.
- Use the connection to choose the two regions. Bilateral transaction repricing cannot be presented as the cause of all provincial GDP or household effects.
- Separate the upstream price assumption from any retail-price assumption. Electricity and failed gas pass-through models cannot silently inherit a bill percentage.
- Keep one stage visible at a time. The selected trade remains the visual anchor. Source details and historical tests remain available on demand.
